# gemsub

[English](README.md) | [فارسی](README.fa.md) | [Русский](README.ru.md)

[![CI](https://github.com/amirreza-a2a/gemsub/actions/workflows/ci.yml/badge.svg)](https://github.com/amirreza-a2a/gemsub/actions/workflows/ci.yml)

`gemsub` — это Go CLI/TUI демон для тестирования прокси-подписок с реальной валидацией целевых сервисов, проверкой совместимости с Google Gemini, планированием проверок, сохранением состояния и опциональной публикацией в Git.

Программа принимает исходные ссылки на прокси из внешних источников, проверяет связность на транспортном уровне и доступность целевого сервиса с помощью двухэтапного активного тестирования, а затем раздает проверенные и классифицированные конфигурации через локальный HTTP-сервер подписок или удаленный Git-репозиторий.

> [!NOTE]
> **Статус релиза**: В репозитории ведется подготовка к выпуску версии **`v0.1.2`**. Предыдущий стабильный релиз — **`v0.1.1`**.

## Ключевые возможности

- **Двухэтапное активное тестирование:** Сочетание проверок сетевого транспорта (TCP/TLS/uTLS) с реальной валидацией на прикладном уровне HTTP против целевых сервисов (таких как Google Gemini).
- **Две канонические проекции:** Разделение пула конфигураций на строго проверенные для Gemini и общие работоспособные в сети узлы на основе единого авторитетного хранилища (Store).
- **Интерактивный терминальный интерфейс (TUI):** Разработан на базе Bubble Tea и Lip Gloss; включает динамическую таблицу узлов, автоматическое маскирование учетных данных (`[REDACTED]`), флаги стран (`auto`, `unicode`, `ascii`), модальное окно деталей и копирование ссылки в буфер обмена одной клавишей (`y`).
- **Интерактивный центр конфигурации (Config Center):** Встроенный менеджер настроек (`c`) в TUI для оперативного управления источниками, параметрами тестирования, таймером планировщика и диагностикой публикации в Git.
- **Мастер начальной настройки (Onboarding Wizard):** Интерактивный 5-шаговый мастер, помогающий проверить первичный источник, настроить локальный саб-сервер, задать параметры тестирования и атомарно сохранить конфигурацию при первом запуске.
- **Фоновый режим демона (Headless Mode):** Легковесная работа в фоне для Linux-серверов, сервисов systemd и ограниченных окружений без инициализации TUI.
- **Динамическое применение конфигурации (Dynamic Propagation):** Потокобезопасный сервис конфигурации с атомарной записью на диск и оперативным обновлением настроек (Hot-Reload) во время работы без перезапуска процесса.
- **Локальный HTTP-сервер подписок:** Раздача автоматически обновляемых подписок для клиентов Throne, Sing-box, Clash и v2rayN с выделенными маршрутами (`/sub/generic`, `/sub/gemini`), фильтрацией по протоколам (`?proto=vless`), выбором формата (`?format=raw` или `?format=base64`) и эндпоинтом проверки состояния (`/healthz`).
- **Автоматическая публикация в Git:** Детерминированный экспорт, фиксация изменений и отправка проверенных конфигураций (`generic/`, `gemini/`, `meta.json`) в удаленный Git-репозиторий.
- **Персистентность и история:** Сохранение ограниченной кольцевой истории циклов, счетчиков временных сбоев и экспоненциального рейтинга надежности между перезапусками в атомарных снапшотах, сжатых gzip (`.json.gz`).
- **Поддерживаемые протоколы:** VLESS, VMess, Trojan и Shadowsocks (`ss://`).

## Архитектура

`gemsub` строго соблюдает архитектурные границы между получением данных, планированием, тестированием, авторитетным управлением состоянием, представлением и доставкой:

```text
Upstream Sources (HTTP URLs / Local Files)
                 │
                 ▼
       Source Service & Normalizer
                 │
                 ▼
          Scheduler Loop ◄─── Control Service (Start / Pause / Resume / Run Now)
                 │
                 ▼
          Tester / Prober
         ┌────────────────────────────────────────┐
         │ Stage 1: Transport & Health (204 Check)│
         │ Stage 2: Target & Gemini (uTLS Probe)  │
         └────────────────────────────────────────┘
                 │
                 ▼
         Authoritative Store
         ┌────────────────────────────────────────┐
         │ - Bounded History & Reliability Score  │
         │ - Atomic Gzip Snapshots (.json.gz)     │
         │ - Dual Projections:                    │
         │   ├── NetworkPassing() → Generic       │
         │   └── Passing()        → Gemini        │
         └───────────────────┬────────────────────┘
                             │
            ┌────────────────┴────────────────┐
            ▼                                 ▼
     HTTP Subserver                     Git Publisher
     (/sub, /sub/generic,              (generic/, gemini/,
      /sub/gemini, /healthz)            meta.json)
```

Хранилище **Store** является единственным авторитетным источником состояния кандидатов, их работоспособности, оценки надежности и принадлежности к проекциям. Слои представления (TUI) и доставки (Subserver, Publisher) используют эти канонические проекции напрямую, не дублируя логику классификации или ранжирования.

## Быстрый старт

### 1. Интерактивный первый запуск (Onboarding Wizard)

Если запустить `gemsub` в интерактивном терминале при отсутствии конфигурационного файла, автоматически откроется 5-шаговый мастер начальной настройки:

```bash
gemsub
```

Мастер последовательно проведет вас через следующие шаги:
1. **Welcome & Architecture:** Обзор архитектуры активного конвейера тестирования и модели проекций.
2. **Primary Subscription Source:** Добавление и валидация первого входящего URL подписки.
3. **Local Subserver Setup:** Настройка локального адреса прослушивания (по умолчанию `127.0.0.1:8765`) и пути к подписке (по умолчанию `/sub`).
4. **Testing & Gemini Defaults:** Настройка параллелизма проверок, таймаутов и целевых URL.
5. **Review & Save:** Проверка параметров, атомарное сохранение в `config.json` и мгновенный запуск фонового цикла тестирования.

### 2. Первый запуск в фоновом режиме (Headless)

В режиме без интерфейса наличие файла конфигурации обязательно. Если файл `config.json` отсутствует:

```bash
gemsub -headless
```

`gemsub` завершит работу с кодом 1 и выведет подсказку:

```text
Configuration file not found: ./config.json

To configure gemsub:
  1. Run gemsub interactively without --headless to launch the onboarding wizard: gemsub
  2. Or create ./config.json manually by copying config.example.json:
     cp config.example.json ./config.json
```

### 3. Ручная настройка

Вы также можете создать конфигурационный файл вручную из примера:

```bash
cp config.example.json config.json
gemsub -config config.json
```

Либо сразу запустить программу как фоновый демон:

```bash
gemsub -headless -config config.json
```

После запуска проверенные ленты подписок сразу же становятся доступны:

```bash
# Получить прокси, проверенные для Gemini (по умолчанию в Base64)
curl -s http://127.0.0.1:8765/sub

# Получить прокси с рабочей сетью в виде обычного текста
curl -s "http://127.0.0.1:8765/sub/generic?format=raw"

# Запросить метрики и статус сервера подписок
curl -s http://127.0.0.1:8765/healthz
```

## Установка

### Linux

#### Автоматический скрипт установки (рекомендуется)

Скрипт автоматически определяет архитектуру системы, загружает релизный архив, сверяет контрольную сумму SHA-256 с файлом `checksums.txt` и атомарно устанавливает бинарный файл в `~/.local/bin`:

```bash
curl -sSfL https://raw.githubusercontent.com/amirreza-a2a/gemsub/main/scripts/install.sh | bash
```

Для установки конкретной версии:

```bash
curl -sSfL https://raw.githubusercontent.com/amirreza-a2a/gemsub/main/scripts/install.sh | bash -s -- -v v0.1.0
```

Для установки в общесистемный каталог `/usr/local/bin` (требуется `sudo`):

```bash
curl -sSfL https://raw.githubusercontent.com/amirreza-a2a/gemsub/main/scripts/install.sh | bash -s -- --system
```

#### Ручная установка из архива

1. Загрузите архив для вашей архитектуры со страницы GitHub Releases:
   - `x86_64` (`amd64`): `gemsub_Linux_x86_64.tar.gz`
   - `arm64` (`aarch64`): `gemsub_Linux_arm64.tar.gz`
   - `armv7` (`armhf`): `gemsub_Linux_armv7.tar.gz`
2. Загрузите `checksums.txt` и проверьте контрольную сумму:
   ```bash
   sha256sum --ignore-missing -c checksums.txt
   ```
3. Распакуйте архив и установите исполняемый файл:
   ```bash
   tar -xzf gemsub_Linux_x86_64.tar.gz
   install -m 755 gemsub ~/.local/bin/gemsub
   ```

#### Системные пакеты Linux (.deb / .rpm)

Debian / Ubuntu:
```bash
sudo dpkg -i gemsub_<version>_linux_<arch>.deb
```

RHEL / Fedora:
```bash
sudo rpm -i gemsub_<version>_linux_<arch>.rpm
```

> [!NOTE]
> Это **автономный артефакт, совместимый с Termux**, собранный для 64-битных ARM-устройств (`aarch64`) под управлением Termux. Физическое тестирование на различных устройствах продолжается; корректность подтверждена герметичными сборками и интеграционными тестами.

Запустите скрипт установки внутри сессии Termux:

```bash
curl -sSfL https://raw.githubusercontent.com/amirreza-a2a/gemsub/main/scripts/install-termux.sh | bash
```

Скрипт проверяет окружение Termux, валидирует архитектуру процессора, сверяет контрольные суммы SHA-256 по `checksums.txt` и помещает исполняемый файл в `$PREFIX/bin/gemsub` без необходимости прав root.

## Терминальный интерфейс (TUI)

TUI обеспечивает мониторинг в реальном времени и интерактивное управление конфигурацией. Рекомендуемый минимальный размер терминала — **80 колонок × 24 строки**.

### Просмотр кандидатов (`ViewCandidates`)

Отображает таблицу проверенных узлов, задержку, результат тестирования, протокол и маскированную ссылку.

| Клавиша | Контекст | Действие |
| :--- | :--- | :--- |
| `Up` / `k` | Таблица | Переместить курсор вверх |
| `Down` / `j` | Таблица | Переместить курсор вниз |
| `PageUp` / `Ctrl+B` | Таблица | Страница вверх |
| `PageDown` / `Ctrl+F` | Таблица | Страница вниз |
| `Home` / `g` | Таблица | В начало таблицы |
| `End` / `G` | Таблица | В конец таблицы |
| `Enter` / `Space` | Таблица | Открыть модальное окно с деталями кандидата |
| `s` | Таблица | Переключить фильтр: все кандидаты / только прошедшие проверку |
| `y` | Таблица | Скопировать полную немаскированную ссылку кандидата в буфер обмена |
| `c` | Глобально | Открыть центр конфигурации (Config Center) |
| `Tab` | Глобально | Переключить фокус между таблицей кандидатов и просмотром логов |
| `q` / `Ctrl+C` | Глобально | Корректное завершение работы, сохранение состояния и выход |

*Маскирование учетных данных:* Конфиденциальные параметры (пароли, UUID) в интерфейсе автоматически скрываются (`[REDACTED]`). При копировании клавишей `y` в буфер обмена копируется оригинальная, работоспособная ссылка.

### Просмотр логов (`ViewLogs`)

Отображает структурированные записи логов в реальном времени из кольцевого буфера памяти.

| Клавиша | Контекст | Действие |
| :--- | :--- | :--- |
| `Up` / `k` | Панель логов | Прокрутка вверх (отключает режим автоследования) |
| `Down` / `j` | Панель логов | Прокрутка вниз |
| `PageUp` / `Ctrl+B` | Панель логов | Страница вверх |
| `PageDown` / `Ctrl+F` | Панель логов | Страница вниз |
| `Home` / `g` | Панель логов | Переход к самым старым записям |
| `End` / `G` | Панель логов | Переход к свежим записям (включает автоследование) |
| `f` | Панель логов | Переключить режим автоследования (Follow Mode) |
| `l` (или `1`-`4`) | Панель логов | Циклическое переключение уровня логов: `DEBUG` (1) → `INFO` (2) → `WARN` (3) → `ERROR` (4) |
| `c` | Глобально | Открыть центр конфигурации (Config Center) |
| `Tab` | Глобально | Вернуться к таблице кандидатов |
| `q` / `Ctrl+C` | Глобально | Корректное завершение работы, сохранение состояния и выход |

### Центр конфигурации (`ViewConfig`)

Нажмите `c` на экране кандидатов или логов для входа в центр конфигурации. Нажмите `Esc` для возврата.

- **Навигация по разделам:** `Tab` / `l` / `Right` (следующий раздел), `Shift+Tab` / `h` / `Left` (предыдущий раздел).
- **Разделы настроек:**
  1. **General:** Адрес и порт сервера подписок, путь, формат по умолчанию, режим отображения флагов стран, путь к файлу состояния.
  2. **Sources:** Управление источниками подписок в реальном времени:
     - `j` / `k` / `g` / `G`: Выбор источника в списке.
     - `Space` или `e`: Включить или отключить выбранный источник.
     - `a`: Добавить новый URL источника и отображаемое имя через диалоговое окно.
     - `Enter`: Редактировать выбранный URL или имя.
     - `d` или `x`: Удалить выбранный источник (требует подтверждения клавишей `y`).
  3. **Testing:** Параллелизм, общий таймаут, таймаут подключения (Dial Timeout), ограничение RPS, количество повторов, пауза между повторами, лимит нерезультативных циклов. Редактируется по нажатию `Enter`, `Space` или `e`.
  4. **Gemini:** Целевой URL проверки и список фраз для выявления региональной блокировки. Редактируется по нажатию `Enter`, `Space` или `e`.
  5. **Scheduler:** Телеметрия таймера (статус, время следующего цикла, завершено циклов, длительность последнего цикла):
     - `p` / `P`: Поставить на паузу или возобновить работу планировщика.
     - `r` / `R`: Запустить цикл тестирования немедленно вне очереди ("Run Now").
     - `Enter` / `Space` / `e`: Изменить интервал цикла или лимит кандидатов на цикл.
  6. **Publishing:** Статус, диагностика и параметры публикации в Git:
     - `e` / `E`: Включить или отключить публикацию.
     - `p` / `P`: Выполнить публикацию в удаленный репозиторий прямо сейчас (запрос подтверждения `y`/`n`).
     - `t` / `T`: Запустить диагностический тест подключения (проверка локального репозитория, связи с удаленным сервером и прав).
     - `r` / `R` или `Enter`: Изменить путь к репозиторию, ветку или удаленный URL.

## Конфигурация

Конфигурация хранится в формате JSON (по умолчанию `./config.json`). Шаблон с комментариями представлен в файле `config.example.json`.

```json
{
  "sources": [
    {
      "url": "https://raw.githubusercontent.com/example/vpn/main/sub.txt",
      "name": "Primary Source",
      "enabled": true
    }
  ],
  "fetch_interval": "3h",
  "test": {
    "health_url": "https://www.gstatic.com/generate_204",
    "health_timeout": "4s",
    "gemini": {
      "url": "https://gemini.google.com/",
      "block_phrases": [
        "isn't currently supported in your country",
        "not available in your country",
        "not available in your region"
      ]
    },
    "timeout": "10s",
    "dial_timeout": "4s",
    "concurrency": 40,
    "rate_limit_rps": 20,
    "max_retries": 2,
    "retry_backoff": "1s",
    "max_inconclusive_cycles": 2
  },
  "serve": {
    "listen": "127.0.0.1:8765",
    "path": "/sub",
    "format": "base64"
  },
  "publishing": {
    "enabled": false,
    "repository": "~/gemsub-subscriptions",
    "branch": "main",
    "remote_url": "git@github.com:your-user/your-subscriptions.git"
  },
  "state_file": "./gemsub_state.json",
  "headless": false,
  "probe_limit": 0,
  "flag_mode": "auto"
}
```

### Справочник параметров конфигурации

| Параметр | Тип | По умолчанию | Описание |
| :--- | :--- | :--- | :--- |
| `sources` | `[]SourceItem` / `[]string` | `[]` | Источники ссылок на подписки (URL или локальные файлы). Поддерживает массив объектов (`id`, `url`, `name`, `enabled`) или обычных строк. |
| `fetch_interval` | `string` | `"3h"` | Интервал между запланированными циклами тестирования (минимум `"1m"`, например `"3h"` или `"45m"`). |
| `test.health_url` | `string` | `"https://www.gstatic.com/generate_204"` | Эндпоинт для проверки сетевой связности на первом этапе. |
| `test.health_timeout` | `string` | `"4s"` | Таймаут проверки сетевого транспорта на первом этапе. |
| `test.gemini.url` | `string` | `"https://gemini.google.com/"` | Целевой эндпоинт для валидации доступа к Gemini на втором этапе. *(Устаревший псевдоним: `test.target_url`)* |
| `test.gemini.block_phrases` | `[]string` | *(встроенные фразы)* | Подстроки в теле ответа, указывающие на региональную блокировку сервиса. *(Устаревший псевдоним: `test.block_phrases`)* |
| `test.timeout` | `string` | `"10s"` | Максимальное суммарное время проверки одного кандидата. |
| `test.dial_timeout` | `string` | `"4s"` | Таймаут установки TCP-соединения и TLS-хендшейка. |
| `test.concurrency` | `int` | `20` | Максимальное число параллельно проверяемых кандидатов в цикле. |
| `test.rate_limit_rps` | `int` | `0` (без лимита) | Глобальное ограничение запросов в секунду (RPS) во время тестирования. |
| `test.max_retries` | `int` | `2` | Число повторных попыток перед тем, как пометить результат как неопределенный (`0` — только одна попытка без повторов). |
| `test.retry_backoff` | `string` | `"1s"` | Пауза между повторными попытками тестирования. |
| `test.max_inconclusive_cycles` | `int` | `2` | Количество последовательных неопределенных циклов перед исключением кандидата из списка рабочих. |
| `serve.listen` | `string` | `"127.0.0.1:8765"` | Сетевой адрес и порт локального HTTP-сервера подписок. |
| `serve.path` | `string` | `"/sub"` | Базовый URL-путь для раздачи подписки. |
| `serve.format` | `string` | `"base64"` | Формат кодирования ленты по умолчанию: `"base64"` или `"raw"`. |
| `publishing.enabled` | `bool` | `false` | Включить автоматическую публикацию проверенных конфигураций в репозиторий Git. |
| `publishing.repository` | `string` | `""` | Локальный путь к целевому репозиторию Git (обязателен при включенной публикации). |
| `publishing.branch` | `string` | `"main"` | Ветка Git для фиксации коммитов публикации. |
| `publishing.remote_url` | `string` | `""` | URL удаленного репозитория Git для проверки безопасности источника origin (обязателен при включенной публикации). |
| `state_file` | `string` | `"./gemsub_state.json"` | Путь к файлу снапшота состояния (автоматически сохраняется в сжатом виде с расширением `.json.gz`). |
| `headless` | `bool` | `false` | Режим работы по умолчанию (`true` — запуск без графического интерфейса TUI). |
| `probe_limit` | `int` | `0` | Лимит количества проверяемых кандидатов за один цикл (`0` — проверять всех). |
| `flag_mode` | `string` | `"auto"` | Режим отображения флагов стран в TUI: `"auto"`, `"unicode"` или `"ascii"`. |

### Политика применения настроек: горячее обновление (Hot-Reload) против перезапуска

`gemsub` разделяет параметры на применяемые немедленно в процессе работы и требующие полного перезапуска демона:

| Политика | Параметры конфигурации | Поведение |
| :--- | :--- | :--- |
| **Hot-Reloadable** | `sources`<br>`fetch_interval`<br>`probe_limit`<br>`flag_mode`<br>`serve.format`<br>`test.health_url`<br>`test.health_timeout`<br>`test.gemini.url`<br>`test.gemini.block_phrases`<br>`test.timeout`<br>`test.dial_timeout`<br>`test.concurrency`<br>`test.rate_limit_rps`<br>`test.max_retries`<br>`test.retry_backoff`<br>`test.max_inconclusive_cycles`<br>`publishing.enabled`<br>`publishing.repository`<br>`publishing.branch`<br>`publishing.remote_url` | Применяются сразу после сохранения во всех запущенных подсистемах (Scheduler, Tester, Subserver, Publisher) без перезапуска процесса. |
| **Restart Required** | `serve.listen`<br>`serve.path`<br>`state_file`<br>`headless` | Немедленно записываются в `config.json`, но помечаются в центре конфигурации как ожидающие перезапуска, поскольку открытые сокеты, пути к снапшотам и режим процесса невозможно безопасно переинициализировать на лету. |

## Модель тестирования и валидации кандидатов

`gemsub` использует активный многоэтапный конвейер тестирования, гарантируя публикацию только стабильных узлов:

```text
Raw Sources → Link Ingestion → Normalization & Deduplication
                                         ↓
                     Stage 1: Transport Health Check
                       (TCP Connect, TLS / uTLS Handshake)
                                         ↓
                     Stage 2: Application Target Check
                       (HTTP Request to Target Endpoint)
                                         ↓
                     Content Inspection & Gate Evaluation
                                         ↓
                     Authoritative Store & State Update
```

1. **Прием и нормализация:** Разбор исходных строк, извлечение параметров протокола и канонизация ссылок для предотвращения повторных тестов.
2. **Проверка транспорта:** Оценка транспортного уровня прокси с помощью ядра `sing-box` с имитацией клиентских отпечатков uTLS. При сбое TCP-соединения, ошибках рукопожатия TLS или недоступности проверочного эндпоинта кандидат классифицируется как транспортная ошибка (`conn_refused`, `timeout`, `tls_error`, `reality_error`).
3. **Валидация приложения:** Узлы с исправным транспортом переходят к тестированию прикладного уровня путем отправки запроса к целевому сервису.
4. **Рейтинг надежности и история:**
   - Каждый кандидат хранит ограниченный кольцевой буфер истории (до 5 последних результатов).
   - Кратковременные сбои (потеря пакетов, кратковременный лимит запросов) классифицируются как `inconclusive` (неопределенные). Ранее работоспособные узлы остаются в выдаче в течение до `test.max_inconclusive_cycles` циклов.
   - Успешные тесты формируют высокий рейтинг надежности на основе алгоритма экспоненциального затухания (`decay_lambda`), определяющий порядок сортировки в выдаче.

## Специализированная проверка для Google Gemini

Стандартные утилиты проверки прокси ориентируются лишь на TCP-пинг или проверку доступности Google 204. Для Google Gemini этого недостаточно:

1. **Региональные ограничения:** Прокси, расположенные в неподдерживаемых странах (или чья геолокация IP определена некорректно), успешно подключаются к Google CDN, но получают страницу с отказом в обслуживании.
2. **Скрытые блокировки:** При блокировках эндпоинты Gemini могут возвращать статус HTTP 200 или 403 со специальным текстом:
   - *"isn't currently supported in your country"*
   - *"not available in your country"*
   - *"not available in your region"*
3. **Блокировка отпечатков TLS:** Фронтенды Google могут ограничивать нестандартные или небраузерные рукопожатия TLS.

`gemsub` решает эту проблему путем эмуляции TLS Client Hello реального браузера через uTLS, установки подлинной HTTP-сессии с `https://gemini.google.com/` и сверки ответа со списком `block_phrases`. Узлы с региональными блокировками изолируются с категорией `region_blocked`.

## Сравнение проекций Generic и Gemini

Авторитетное хранилище `Store` формирует две полностью независимые проекции:

```text
                    ┌─────────────────────────┐
                    │       Store State       │
                    └────────────┬────────────┘
                                 │
                 ┌───────────────┴───────────────┐
                 ▼                               ▼
      Store.NetworkPassing()               Store.Passing()
    [Generic Network Projection]       [Gemini-Verified Projection]
                 │                               │
                 ▼                               ▼
        /sub/generic or                  /sub/gemini or
        /sub?projection=generic          /sub?projection=gemini
```

- **Общая сетевая проекция (`Store.NetworkPassing()`):** Включает все узлы, успешно прошедшие проверку сетевого транспорта (`https://www.gstatic.com/generate_204`), независимо от того, блокирует ли их Gemini. Рекомендуется для общего веб-серфинга, мессенджеров и задач вне инфраструктуры Gemini.
- **Проекция для Gemini (`Store.Passing()`):** Включает исключительно те узлы, которые успешно прошли как проверку транспорта, так и валидацию доступа к Gemini. Предназначена для работы с ИИ и сервисами, чувствительными к региону.

## Уровни доставки

### HTTP-сервер подписок

Встроенный сервер отдает актуальные ленты подписок клиентам:

- **Базовый эндпоинт:** `http://127.0.0.1:8765/sub` (по умолчанию отдает проекцию Gemini).
- **Выделенный эндпоинт Generic:** `http://127.0.0.1:8765/sub/generic` (отдает общую сетевую проекцию).
- **Выделенный эндпоинт Gemini:** `http://127.0.0.1:8765/sub/gemini` (отдает проекцию, проверенную для Gemini).
- **Эндпоинт мониторинга:** `http://127.0.0.1:8765/healthz` (JSON со статусом, числом рабочих узлов для Gemini, общим числом рабочих узлов в сети, общим числом в базе и временем последнего цикла).

#### Параметры запроса
- `projection=generic` или `projection=gemini`: Выбор проекции на базовом пути `/sub`.
- `proto=vless`, `proto=vmess` или `proto=trojan`: Фильтрация по протоколу (псевдоним `protocol=`).
- `format=raw` или `format=base64`: Переопределение формата выдачи для конкретного запроса.

#### Примеры
```bash
# Получить подписку Gemini в кодировке Base64 (по умолчанию):
curl -s "http://127.0.0.1:8765/sub"

# Получить рабочие прокси общей проекции в виде обычного текста:
curl -s "http://127.0.0.1:8765/sub/generic?format=raw"

# Получить только VLESS-прокси для Gemini в виде обычного текста:
curl -s "http://127.0.0.1:8765/sub/gemini?proto=vless&format=raw"

# Проверить статус здоровья и метрики:
curl -s "http://127.0.0.1:8765/healthz"
```

### Публикация в Git

При включенном параметре `publishing.enabled` программа фиксирует и отправляет проверенные конфигурации в указанный Git-репозиторий по окончании каждого цикла:

```text
<repository>/
├── generic/
│   ├── all.txt
│   ├── vless.txt
│   ├── vmess.txt
│   └── trojan.txt
├── gemini/
│   ├── all.txt
│   ├── vless.txt
│   ├── vmess.txt
│   └── trojan.txt
└── meta.json
```

- `generic/*.txt`: Конфигурации, прошедшие 1-й этап проверки (транспорт).
- `gemini/*.txt`: Конфигурации, прошедшие оба этапа проверки (транспорт и Gemini).
- `meta.json`: Несекретные метаданные цикла (время генерации, номер цикла, количество узлов по проекциям).
- Процесс публикации атомарен: изменения проверяются перед фиксацией, а репозиторий контролируется на чистоту рабочего каталога.

## Сохранение состояния (State Persistence)

- Состояние сохраняется в файл, указанный в `state_file` (по умолчанию `./gemsub_state.json`), и автоматически сжимается с помощью gzip в файл `./gemsub_state.json.gz`.
- Запись производится во временный файл с последующим атомарным переименованием, что исключает повреждение данных при внезапном сбое питания или остановке процесса.
- При запуске программа восстанавливает историю, оценки надежности и список узлов до начала нового цикла тестирования. Восстановленные рабочие узлы сразу же становятся доступны для клиентов через сервер подписок.

## Разработка и тестирование

### Команды сборки и проверки

Все операции сборки и тестирования в CI требуют флага `-tags with_utls` для включения эмуляции отпечатков uTLS:

```bash
# Проверка форматирования
gofmt -l .

# Проверка лишних пробелов и строк
git diff --check

# Статический анализ
go vet -tags with_utls ./...

# Модульные тесты (последовательный запуск для точности замеров времени)
go test -tags with_utls -count=1 -p 1 ./...

# Проверка состояния гонки (Race Detector) для пакетов проекта
go test -tags with_utls -race -count=1 ./cmd/gemsub ./internal/config ./internal/scheduler ./internal/publisher ./internal/source ./internal/store ./internal/subserver ./internal/tui

# Сборка исполняемого файла
make build
# или: go build -tags with_utls ./cmd/gemsub
```

> [!NOTE]
> Пакет `internal/tester` тестируется без флага `-race` из-за известного состояния гонки во внешнем мониторе интерфейсов библиотеки `sing-box` (зафиксировано в реестре технического долга как `TD-008`).

## Процесс релиза

Выпуск версий автоматизирован через GitHub Actions и GoReleaser на основе семантических тегов:

1. **Создание тега:** Релиз запускается созданием и отправкой тега версии:
   ```bash
   git tag -a vX.Y.Z -m "Release vX.Y.Z"
   git push origin vX.Y.Z
   ```
2. **Автоматический конвейер (`.github/workflows/release.yml`):**
   - Задача `validate` запускает `go vet` и последовательные тесты с минимальными правами `contents: read`.
   - Задача `release` вызывает GoReleaser v2 (`v2.18.1`) с правами `contents: write`.
   - GoReleaser выполняет кросс-компиляцию, сборку архивов, пакетов `.deb` и `.rpm`, расчет контрольных сумм SHA-256 в `checksums.txt`, внедрение метаданных версии и публикацию в GitHub Releases.
3. **Локальная проверка сборки релизов:**
   Разработчики могут проверить генерацию релиза локально без создания тегов:
   ```bash
   # Проверка корректности конфигурации GoReleaser
   make release-check

   # Генерация тестовых бинарных файлов и пакетов в каталоге ./dist
   make release-snapshot
   ```

## Контрольные суммы и проверка подлинности

Все релизные файлы сопровождаются авторитетным файлом `checksums.txt` с контрольными суммами SHA-256.

### Безопасность автоматических установщиков
Скрипты `scripts/install.sh` и `scripts/install-termux.sh` гарантируют строгую валидацию:
- Точное совпадение имен файлов (защита от неоднозначности подстрок).
- Контроль единственности записи в файле сумм.
- Проверка формата 64-значного шестнадцатеричного хэша SHA-256.
- Удаление поврежденных архивов до их распаковки при несовпадении контрольной суммы.
- Полная поддержка индикатора бинарного режима (`*<filename>`).

### Ручная проверка
```bash
sha256sum --ignore-missing -c checksums.txt
```

## Поддерживаемые платформы и известные ограничения

| Платформа | Архитектура | Формат бинарного файла | Каналы дистрибуции |
| :--- | :--- | :--- | :--- |
| **Linux** | `x86_64` (`amd64`) | Statically linked ELF64 | Скрипт установки, `.tar.gz`, `.deb`, `.rpm` |
| **Linux** | `arm64` (`aarch64`) | Statically linked ELF64 | Скрипт установки, `.tar.gz`, `.deb`, `.rpm` |
| **Linux** | `armv7` (`armhf`) | Statically linked ELF32 | Скрипт установки, `.tar.gz`, `.deb`, `.rpm` |
| **Android / Termux** | `arm64` (`aarch64`) | Position-Independent ELF64 (`DYN`) | Скрипт установки Termux, `.tar.gz` |
| **Windows** | `x86_64` (`amd64`) | Standalone PE64 (`.exe`) | Автономный `.zip` |
| **Windows** | `arm64` | Standalone PE64 (`.exe`) | Автономный `.zip` |

### Известные ограничения
- **Тестирование в среде Termux:** Бинарный файл arm64 для Termux проверен кросс-компиляцией и интеграционными тестами; тестирование на реальных физических устройствах продолжается.
- **Десктопные платформы:** Десктопные сборки для macOS в текущей релизной матрице по-прежнему не формируются. Официальные сборки для Windows поддерживаются для архитектур x86_64 и arm64 в виде автономных архивов ZIP.
- **Состояние гонки в Sing-Box (`TD-008`):** Известное состояние гонки в сетевом мониторе библиотеки `sing-box` (`route/network.go`) при высокой нагрузке с включенным детектором гонок Go. Проблема изолирована в CI и отслеживается в реестре технического долга.

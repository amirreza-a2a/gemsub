# gemsub

[English](README.md) | [فارسی](README.fa.md) | [Русский](README.ru.md)

[![CI](https://github.com/amirreza-a2a/gemsub/actions/workflows/ci.yml/badge.svg)](https://github.com/amirreza-a2a/gemsub/actions/workflows/ci.yml)

نرم‌افزار `gemsub` یک دیمن CLI/TUI نوشته‌شده به زبان Go برای ارزیابی و اعتبارسنجی سابسکریپشن‌های پروکسی با بررسی واقعی دسترسی به سرویس هدف، سنجش سازگاری با Google Gemini، زمان‌بندی چرخه‌ها، ماندگاری وضعیت و انتشار اختیاری در گیت است.

این برنامه لینک‌های خام اشتراک پروکسی را از منابع بالادستی دریافت کرده، پایداری شبکه در سطح لایه انتقال و دسترسی‌پذیری سرویس هدف را از طریق پروب فعال دو مرحله‌ای بررسی می‌کند و پیکربندی‌های معتبر و طبقه‌بندی‌شده را از طریق یک اندپوینت محلی HTTP یا مخزن ریموت Git ارائه می‌دهد.

> [!NOTE]
> **وضعیت انتشار**: مخزن در حال آماده‌سازی برای انتشار نسخه **`v0.1.2`** است. آخرین نسخه پایدار منتشرشده **`v0.1.1`** است.

## ویژگی‌های کلیدی

- **پروب فعال دو مرحله‌ای:** ترکیب بررسی سلامت لایه انتقال (TCP/TLS/uTLS) با ارزیابی واقعی لایه اپلیکیشن HTTP در برابر سرویس هدف (نظیر Google Gemini).
- **دو پروجکشن مجزا و مستقل:** تفکیک و استخراج دو خروجی مجزا شامل پروجکشن تاییدشده ویژه جمینای و پروجکشن عمومی شبکه بر پایه یک Store مرجع واحد.
- **رابط کاربری تعاملی ترمینال (TUI):** توسعه‌یافته با Bubble Tea و Lip Gloss؛ شامل جدول لحظه‌ای کانفیگ‌ها، ماسک‌سازی خودکار داده‌های حساس (`[REDACTED]`)، پرچم کشورها (`auto`، `unicode`، `ascii`)، پنجره بررسی جزئیات و کپی تک‌کلیدی لینک اشتراک (`y`).
- **مرکز پیکربندی تعاملی (Config Center):** مدیریت زنده تنظیمات در محیط TUI با کلید `c` برای منابع اشتراک، پارامترهای اجرایی، کنترل زمان‌بندی (Scheduler) و عیب‌یابی انتشار در گیت.
- **ویزارد راه‌اندازی اولیه (Onboarding Wizard):** فرآیند راهنمای ۵ مرحله‌ای برای سنجش منابع اولیه، راه‌اندازی ساب‌سرور محلی، تنظیم پارامترهای تست و ذخیره اتمیک تنظیمات در اولین اجرا.
- **حالت بدون رابط کاربری (Headless Daemon):** اجرای سبک در پس‌زمینه مناسب برای سرورهای لینوکسی، سرویس‌های systemd و محیط‌های محدود بدون نیاز به راه‌اندازی TUI.
- **انتشار پویای پیکربندی (Dynamic Configuration Propagation):** سرویس پیکربندی همگام و ایمن در برابر همروندی با ذخیره‌سازی اتمیک و اعمال بلادرنگ (Hot-Reload) تنظیمات اجرایی بدون نیاز به ری‌استارت دیمن.
- **سرور اشتراک محلی HTTP:** تحویل سابسکریپشن‌های خودکار به کلاینت‌هایی نظیر Throne، Sing-box، Clash و v2rayN با مسیرهای اختصاصی (`/sub/generic`، `/sub/gemini`)، فیلتر پروتکل (`?proto=vless`)، انتخاب فرمت (`?format=raw` یا `?format=base64`) و اندپوینت بررسی سلامت (`/healthz`).
- **انتشار خودکار در گیت (Git Publishing):** خروجی قطعی و ارسال خودکار پیکربندی‌های تاییدشده (`generic/`، `gemini/`، `meta.json`) به یک مخزن ریموت Git.
- **ماندگاری داده‌ها و تاریخچه چرخه‌ها:** حفظ تاریخچه حلقوی محدود چرخه‌ها، پیگیری خطاهای گذرا و امتیازدهی نمایی پایداری در قالب اسنپ‌شات‌های اتمیک فشرده‌شده با gzip (`.json.gz`).
- **پروتکل‌های پشتیبانی‌شده:** VLESS، VMess، Trojan و Shadowsocks (`ss://`).

## نمای کلی معماری

نرم‌افزار `gemsub` مرزهای دقیق معماری میان دریافت منابع، زمان‌بندی، پروب، مدیریت مرجع وضعیت، نمایش و تحویل را رعایت می‌کند:

```text
Upstream Sources (HTTP URLs / Local Files)
                 │
                 ▼
       Source Service & Normalizer
                 │
                 ▼
          Scheduler Loop ◄─── Control Service (Start / Pause / Resume / Run Now)
                 │
                 ▼
          Tester / Prober
         ┌────────────────────────────────────────┐
         │ Stage 1: Transport & Health (204 Check)│
         │ Stage 2: Target & Gemini (uTLS Probe)  │
         └────────────────────────────────────────┘
                 │
                 ▼
         Authoritative Store
         ┌────────────────────────────────────────┐
         │ - Bounded History & Reliability Score  │
         │ - Atomic Gzip Snapshots (.json.gz)     │
         │ - Dual Projections:                    │
         │   ├── NetworkPassing() → Generic       │
         │   └── Passing()        → Gemini        │
         └───────────────────┬────────────────────┘
                             │
            ┌────────────────┴────────────────┐
            ▼                                 ▼
     HTTP Subserver                     Git Publisher
     (/sub, /sub/generic,              (generic/, gemini/,
      /sub/gemini, /healthz)            meta.json)
```

بخش **Store** مرجع واحد و قطعی وضعیت کاندیداها، سلامت، امتیازدهی و عضویت در پروجکشن‌ها است. لایه‌های نمایش (TUI) و تحویل (Subserver و Publisher) مستقیماً از این پروجکشن‌های معتبر استفاده کرده و هیچ منطق طبقه‌بندی یا امتیازدهی مجزایی در آن‌ها بازتولید نمی‌شود.

## شروع سریع

### ۱. اجرای اولیه تعاملی (Onboarding Wizard)

هنگامی که `gemsub` به‌صورت تعاملی بدون فایل پیکربندی قبلی اجرا شود، به‌طور خودکار ویزارد راه‌اندازی ۵ مرحله‌ای را باز می‌کند:

```bash
gemsub
```

مراحل ویزارد:
1. **Welcome & Architecture:** مروری بر معماری خط لوله تست فعال و مدل پروجکشن‌ها.
2. **Primary Subscription Source:** دریافت و اعتبارسنجی اولیه آدرس منبع سابسکریپشن بالادستی.
3. **Local Subserver Setup:** تنظیم آدرس شبکه محلی (پیش‌فرض `127.0.0.1:8765`) و مسیر سابسکریپشن (پیش‌فرض `/sub`).
4. **Testing & Gemini Defaults:** تنظیم نرخ همروندی پروب‌ها، محدودیت زمانی (Timeout) و نشانی هدف.
5. **Review & Save:** بررسی تنظیمات تولیدشده، ثبت اتمیک در `config.json` و شروع بلافاصله زمان‌بندی و پروب کاندیداها.

### ۲. اجرای اولیه در حالت Headless

در حالت headless وجود فایل پیکربندی الزامی است. در صورت نبود `config.json`:

```bash
gemsub -headless
```

برنامه با کد خطای ۱ متوقف شده و راهنمایی زیر را چاپ می‌کند:

```text
Configuration file not found: ./config.json

To configure gemsub:
  1. Run gemsub interactively without --headless to launch the onboarding wizard: gemsub
  2. Or create ./config.json manually by copying config.example.json:
     cp config.example.json ./config.json
```

### ۳. پیکربندی دستی

همچنین می‌توانید فایل پیکربندی را به‌صورت دستی از قالب آماده الگوبرداری کنید:

```bash
cp config.example.json config.json
gemsub -config config.json
```

یا مستقیماً به‌عنوان یک دیمن پس‌زمینه اجرا نمایید:

```bash
gemsub -headless -config config.json
```

پس از راه‌اندازی، فیدهای اعتبارسنجی‌شده بلافاصله در دسترس هستند:

```bash
# دریافت پروکسی‌های تاییدشده برای جمینای (فرمت پیش‌فرض Base64)
curl -s http://127.0.0.1:8765/sub

# دریافت پروکسی‌های سالم شبکه به‌صورت متن خام
curl -s "http://127.0.0.1:8765/sub/generic?format=raw"

# استعلام وضعیت و متریک‌های ساب‌سرور
curl -s http://127.0.0.1:8765/healthz
```

## نصب

### لینوکس

#### اسکریپت نصب خودکار (پیشنهادی)

اسکریپت خودکار نصب لینوکس معماری پردازنده را تشخیص داده، آرشیو نسخه متناسب را دانلود می‌کند، اعتبار چکسام SHA-256 را در برابر `checksums.txt` می‌سنجد و فایل باینری را در مسیر `~/.local/bin` مستقر می‌نماید:

```bash
curl -sSfL https://raw.githubusercontent.com/amirreza-a2a/gemsub/main/scripts/install.sh | bash
```

برای نصب یک نسخه خاص:

```bash
curl -sSfL https://raw.githubusercontent.com/amirreza-a2a/gemsub/main/scripts/install.sh | bash -s -- -v v0.1.0
```

برای نصب در سطح کل سیستم در مسیر `/usr/local/bin` (نیازمند `sudo`):

```bash
curl -sSfL https://raw.githubusercontent.com/amirreza-a2a/gemsub/main/scripts/install.sh | bash -s -- --system
```

#### نصب دستی از آرشیو

۱. آرشیو مناسب معماری پردازنده خود را از بخش GitHub Releases دانلود کنید:
   - `x86_64` (`amd64`): `gemsub_Linux_x86_64.tar.gz`
   - `arm64` (`aarch64`): `gemsub_Linux_arm64.tar.gz`
   - `armv7` (`armhf`): `gemsub_Linux_armv7.tar.gz`
۲. فایل `checksums.txt` را دریافت کرده و اصالت فایل را بررسی کنید:
   ```bash
   sha256sum --ignore-missing -c checksums.txt
   ```
۳. فایل را استخراج و نصب کنید:
   ```bash
   tar -xzf gemsub_Linux_x86_64.tar.gz
   install -m 755 gemsub ~/.local/bin/gemsub
   ```

#### بسته‌های سیستمی لینوکس (.deb / .rpm)

دبیان / اوبونتو:
```bash
sudo dpkg -i gemsub_<version>_linux_<arch>.deb
```

فدورا / RHEL:
```bash
sudo rpm -i gemsub_<version>_linux_<arch>.rpm
```

## رابط کاربری ترمینال (TUI)

رابط کاربری TUI امکان نظارت زنده و مدیریت تعاملی تنظیمات را فراهم می‌کند. حداقل اندازه پیشنهادی ترمینال **۸۰ ستون × ۲۴ سطر** است.

### نمای کاندیداها (`ViewCandidates`)

جدول پروکسی‌های بررسی‌شده، تاخیر زمانی، نتیجه تست، پروتکل و لینک ماسک‌شده را نمایش می‌دهد.

| کلید | موقعیت | عملکرد |
| :--- | :--- | :--- |
| `Up` / `k` | جدول | انتقال انتخاب‌گر به بالا |
| `Down` / `j` | جدول | انتقال انتخاب‌گر به پایین |
| `PageUp` / `Ctrl+B` | جدول | یک صفحه به بالا |
| `PageDown` / `Ctrl+F` | جدول | یک صفحه به پایین |
| `Home` / `g` | جدول | رفتن به ابتدای جدول |
| `End` / `G` | جدول | رفتن به انتهای جدول |
| `Enter` / `Space` | جدول | باز کردن پنجره جزئیات کاندیدا |
| `s` | جدول | جابه‌جایی فیلتر بین همه کاندیداها و فقط کاندیداهای معتبر |
| `y` | جدول | کپی لینک اصلی و بدون ماسک کاندیدا در کلیپ‌بورد سیستم |
| `c` | سراسری | ورود به مرکز پیکربندی (Config Center) |
| `Tab` | سراسری | جابه‌جایی تمرکز بین نمای کاندیداها و نمای لاگ‌ها |
| `q` / `Ctrl+C` | سراسری | خروج ایمن از برنامه، ذخیره وضعیت در دیسک و پایان پردازش |

*ماسک‌سازی اطلاعات حساس:* اعتبارنامه‌های حساس (رمز عبور، UUID) در صفحه نمایش به شکل `[REDACTED]` ماسک می‌شوند. فشردن کلید `y`، لینک واقعی و بدون ماسک را در کلیپ‌بورد کپی می‌کند.

### نمای لاگ‌ها (`ViewLogs`)

نمایش رکوردهای ساختاریافته لاگ که در یک بافر حافظه حلقوی ذخیره شده‌اند.

| کلید | موقعیت | عملکرد |
| :--- | :--- | :--- |
| `Up` / `k` | پنل لاگ | اسکرول به بالا (غیرفعال‌سازی دنبال‌کردن خودکار) |
| `Down` / `j` | پنل لاگ | اسکرول به پایین |
| `PageUp` / `Ctrl+B` | پنل لاگ | یک صفحه به بالا |
| `PageDown` / `Ctrl+F` | پنل لاگ | یک صفحه به پایین |
| `Home` / `g` | پنل لاگ | پرش به قدیمی‌ترین لاگ |
| `End` / `G` | پنل لاگ | پرش به آخرین لاگ (فعال‌سازی مجدد دنبال‌کردن خودکار) |
| `f` | پنل لاگ | تغییر حالت دنبال‌کردن خودکار لاگ‌ها (Follow Mode) |
| `l` (یا `1` تا `4`) | پنل لاگ | گردش در سطح لاگ: `DEBUG` (1) ← `INFO` (2) ← `WARN` (3) ← `ERROR` (4) |
| `c` | سراسری | ورود به مرکز پیکربندی (Config Center) |
| `Tab` | سراسری | بازگشت به نمای کاندیداها |
| `q` / `Ctrl+C` | سراسری | خروج ایمن از برنامه، ذخیره وضعیت در دیسک و پایان پردازش |

### مرکز پیکربندی (`ViewConfig`)

فشردن کلید `c` از نمای کاندیداها یا لاگ‌ها، مرکز پیکربندی تعاملی را باز می‌کند. کلید `Esc` برای بازگشت استفاده می‌شود.

- **جابه‌جایی میان دسته‌ها:** `Tab` / `l` / `Right` (دسته بعد)، `Shift+Tab` / `h` / `Left` (دسته قبل).
- **دسته‌بندی‌ها:**
  1. **General:** آدرس و پورت ساب‌سرور، مسیر، فرمت خروجی، حالت پرچم کشورها و مسیر فایل وضعیت.
  2. **Sources:** مدیریت زنده منابع اشتراک:
     - `j` / `k` / `g` / `G`: انتخاب منبع.
     - `Space` یا `e`: فعال یا غیرفعال کردن منبع انتخاب‌شده.
     - `a`: افزودن منبع اشتراک جدید (URL و نام نمایشی) در پنجره دیالوگ.
     - `Enter`: ویرایش آدرس یا نام منبع انتخاب‌شده.
     - `d` یا `x`: حذف منبع انتخاب‌شده (با تایید کلید `y`).
  3. **Testing:** نرخ همروندی، محدودیت زمانی پروب، مهلت اتصال (Dial Timeout)، محدودیت RPS، تعداد تلاش مجدد، تاخیر میان تلاش‌ها و حداکثر چرخه‌های نامشخص. با فشردن `Enter`، `Space` یا `e` قابل ویرایش است.
  4. **Gemini:** نشانی سرویس هدف و لیست عبارت‌های شناسایی مسدودسازی منطقه‌ای. با `Enter`، `Space` یا `e` قابل ویرایش است.
  5. **Scheduler:** تله‌متری زمان‌بندی (وضعیت، تخمین چرخه بعد، چرخه‌های کامل‌شده، مدت آخرین چرخه):
     - `p` / `P`: توقف موقت (Pause) یا ازسرگیری (Resume) تایمر زمان‌بندی.
     - `r` / `R`: اجرای فوری یک چرخه پروب خارج از نوبت ("Run Now").
     - `Enter` / `Space` / `e`: ویرایش فاصله زمانی چرخه‌ها یا سقف تعداد کاندیداها در هر چرخه.
  6. **Publishing:** وضعیت، عیب‌یابی و تنظیمات انتشار در Git:
     - `e` / `E`: فعال یا غیرفعال کردن قابلیت انتشار.
     - `p` / `P`: اجرای بلافاصله فرآیند انتشار در مخزن ریموت (با تایید `y`/`n`).
     - `t` / `T`: اجرای تست تشخیصی اتصال (بررسی مخزن محلی، اتصال به ریموت و دسترسی‌ها).
     - `r` / `R` یا `Enter`: ویرایش مسیر مخزن محلی، شاخه یا آدرس ریموت.

## پیکربندی

پیکربندی در قالب یک فایل JSON ذخیره می‌شود (پیش‌فرض `./config.json`). فایل نمونه در `config.example.json` قرار دارد.

```json
{
  "sources": [
    {
      "url": "https://raw.githubusercontent.com/example/vpn/main/sub.txt",
      "name": "Primary Source",
      "enabled": true
    }
  ],
  "fetch_interval": "3h",
  "test": {
    "health_url": "https://www.gstatic.com/generate_204",
    "health_timeout": "4s",
    "gemini": {
      "url": "https://gemini.google.com/",
      "block_phrases": [
        "isn't currently supported in your country",
```

### سیاست بازخوانی: اعمال زنده (Hot-Reload) در برابر نیاز به ری‌استارت

نرم‌افزار `gemsub` بین تنظیماتی که بلافاصله در حین اجرا اعمال می‌شوند و تنظیماتی که نیازمند راه‌اندازی مجدد برنامه هستند تفاوت قائل می‌شود:

| سیاست | فیلدهای پیکربندی | رفتار اجرایی |
| :--- | :--- | :--- |
| **Hot-Reloadable** | `sources`<br>`fetch_interval`<br>`probe_limit`<br>`flag_mode`<br>`serve.format`<br>`test.health_url`<br>`test.health_timeout`<br>`test.gemini.url`<br>`test.gemini.block_phrases`<br>`test.timeout`<br>`test.dial_timeout`<br>`test.concurrency`<br>`test.rate_limit_rps`<br>`test.max_retries`<br>`test.retry_backoff`<br>`test.max_inconclusive_cycles`<br>`publishing.enabled`<br>`publishing.repository`<br>`publishing.branch`<br>`publishing.remote_url` | به‌محض ذخیره، بلافاصله در زیرسیستم‌های فعال (Scheduler، Tester، Subserver، Publisher) بدون نیاز به توقف و ری‌استارت اعمال می‌شوند. |
| **Restart Required** | `serve.listen`<br>`serve.path`<br>`state_file`<br>`headless` | تنظیمات بلافاصله در `config.json` ذخیره می‌شوند؛ اما در مرکز پیکربندی به‌عنوان نیازمند ری‌استارت علامت می‌خورند زیرا سوکت‌های شبکه، مسیر اسنپ‌شات و حالت پردازش در زمان اجرا بدون ایجاد ریسک قابل تغییر مجدد نیستند. |

## مدل تست و اعتبارسنجی کاندیداها

`gemsub` یک خط لوله پروب چندمرحله‌ای فعال را مدیریت می‌کند تا تنها پروکسی‌های پایدار و سالم در خروجی قرار گیرند:

```text
Raw Sources → Link Ingestion → Normalization & Deduplication
                                         ↓
                     Stage 1: Transport Health Check
                       (TCP Connect, TLS / uTLS Handshake)
                                         ↓
                     Stage 2: Application Target Check
                       (HTTP Request to Target Endpoint)
                                         ↓
                     Content Inspection & Gate Evaluation
                                         ↓
                     Authoritative Store & State Update
```

۱. **دریافت و یکپارچه‌سازی:** تجزیه لینک‌های خام، استخراج پارامترهای پروتکل و نرمال‌سازی لینک‌ها برای جلوگیری از تست‌های تکراری.
۲. **پروب لایه انتقال:** ارزیابی لایه انتقال پروکسی با هسته `sing-box` و استفاده از فینگرپرینت‌های مرورگری uTLS. در صورت شکست اتصال TCP، خطای هندشیک TLS یا پاسخ ناموفق از اندپوینت سلامت، کاندیدا به‌عنوان خطای لایه انتقال دسته‌بندی می‌شود (`conn_refused`، `timeout`، `tls_error`، `reality_error`).
۳. **اعتبارسنجی اپلیکیشن:** پروکسی‌هایی که مرحله اول را با موفقیت پشت سر بگذارند وارد مرحله اعتبارسنجی لایه کاربردی با ارسال درخواست به سرویس هدف می‌شوند.
۴. **امتیازدهی پایداری و تاریخچه محدود:**
   - هر کاندیدا یک بافر حلقوی محدود از ۵ نتیجه تست اخیر خود را نگه می‌دارد.
   - خطاهای گذرا (نظیر افت موقت پکت یا محدودیت نرخ) با وضعیت `inconclusive` ثبت می‌شوند. کاندیداهایی که قبلاً سالم بوده‌اند تا سقف `test.max_inconclusive_cycles` در لیست ارائه‌شده باقی می‌مانند.
   - پاس‌شدن مداوم تست‌ها با استفاده از تابع میرایی نمایی (`decay_lambda`) باعث افزایش امتیاز پایداری کاندیدا شده و اولویت قرارگیری آن را در خروجی مشخص می‌کند.

## اعتبارسنجی اختصاصی Google Gemini

تست‌های رایج پروکسی صرفاً به پینگ TCP یا کد وضعیت 204 گوگل اتکا می‌کنند. این روش‌ها برای Google Gemini ناکافی هستند، زیرا:

۱. **محدودیت‌های منطقه‌ای:** پروکسی‌هایی که سرور آن‌ها در کشورهای پشتیبانی‌نشده قرار دارد (یا ژئولوکیشن IP آن‌ها اشتباه ثبت شده) ممکن است به CDN گوگل وصل شوند، اما صفحه خطای دسترسی منطقه‌ای دریافت کنند.
۲. **مسدودسازی‌های خاموش:** هنگام مسدودسازی، اندپوینت‌های جمینای ممکن است کد وضعیت HTTP 200 یا 403 حاوی متن‌های رد دسترسی برگردانند:
   - *"isn't currently supported in your country"*
   - *"not available in your country"*
   - *"not available in your region"*
۳. **رد فینگرپرینت TLS:** سرورهای گوگل ممکن است هندشیک‌های غیرمرورگری TLS را مسدود یا محدود کنند.

نرم‌افزار `gemsub` با شبیه‌سازی دقیق TLS Client Hello مرورگر از طریق uTLS، یک سشن واقعی HTTP به `https://gemini.google.com/` برقرار کرده و محتوای پاسخ را با عبارت‌های `block_phrases` تطبیق می‌دهد. کاندیداهایی که با مسدودسازی روبه‌رو شوند در دسته `region_blocked` قرار می‌گیرند.

## مقایسه پروجکشن‌های عمومی و جمینای

بخش مرجع `Store` دو پروجکشن کاملاً مستقل و تفکیک‌شده را نگهداری می‌کند:

```text
                    ┌─────────────────────────┐
                    │       Store State       │
                    └────────────┬────────────┘
                                 │
                 ┌───────────────┴───────────────┐
                 ▼                               ▼
      Store.NetworkPassing()               Store.Passing()
    [Generic Network Projection]       [Gemini-Verified Projection]
                 │                               │
                 ▼                               ▼
        /sub/generic or                  /sub/gemini or
        /sub?projection=generic          /sub?projection=gemini
```

- **پروجکشن عمومی (`Store.NetworkPassing()`):** شامل تمام کاندیداهایی است که تست لایه انتقال (`https://www.gstatic.com/generate_204`) را با موفقیت گذرانده‌اند، صرف‌نظر از اینکه جمینای آن‌ها را مسدود کرده باشد یا خیر. این پروجکشن برای وبگردی عمومی، پیام‌رسان‌ها و مصارف غیر از جمینای پیشنهاد می‌شود.
- **پروجکشن جمینای (`Store.Passing()`):** منحصراً شامل کاندیداهایی است که هم تست انتقال و هم ارزیابی دسترسی جمینای را پاس کرده‌اند. مناسب برای ابزارهای هوش مصنوعی و سرویس‌های حساس به موقعیت جغرافیایی.

## لایه‌های تحویل

### سرور سابسکریپشن HTTP

ساب‌سرور داخلی فیدهای زنده اشتراک را در اختیار کلاینت‌های پروکسی قرار می‌دهد:

- **اندپوینت پایه:** `http://127.0.0.1:8765/sub` (به‌صورت پیش‌فرض پروجکشن جمینای را تحویل می‌دهد).
- **اندپوینت اختصاصی عمومی:** `http://127.0.0.1:8765/sub/generic` (تحویل پروجکشن عمومی سلامت شبکه).
- **اندپوینت اختصاصی جمینای:** `http://127.0.0.1:8765/sub/gemini` (تحویل پروجکشن تاییدشده جمینای).
- **اندپوینت سلامت و تله‌متری:** `http://127.0.0.1:8765/healthz` (ارائه خروجی JSON از تعداد کاندیداهای معتبر، کاندیداهای معتبر عمومی، کل کاندیداها و زمان آخرین چرخه).

#### پارامترهای کوئری
- `projection=generic` یا `projection=gemini`: انتخاب پروجکشن روی مسیر اصلی `/sub`.
- `proto=vless`، `proto=vmess` یا `proto=trojan`: فیلتر فید بر اساس پروتکل (نام مستعار `protocol=`).
- `format=raw` یا `format=base64`: تغییر فرمت خروجی سابسکریپشن برای هر درخواست.

#### مثال‌ها
```bash
# دریافت سابسکریپشن تاییدشده جمینای با انکودینگ پیش‌فرض Base64:
curl -s "http://127.0.0.1:8765/sub"

# دریافت پروکسی‌های عمومی سالم شبکه به‌صورت متن خام:
curl -s "http://127.0.0.1:8765/sub/generic?format=raw"

# دریافت پروکسی‌های تاییدشده VLESS برای جمینای به‌صورت متن خام:
curl -s "http://127.0.0.1:8765/sub/gemini?proto=vless&format=raw"

# بررسی وضعیت سلامت و آمار سیستم:
curl -s "http://127.0.0.1:8765/healthz"
```

### انتشار در Git

در صورت فعال بودن `publishing.enabled`، برنامه در پایان هر چرخه پیکربندی‌های تاییدشده را در مخزن Git تعیین‌شده کامیت کرده و ارسال (Push) می‌کند:

```text
<repository>/
├── generic/
│   ├── all.txt
│   ├── vless.txt
│   ├── vmess.txt
│   └── trojan.txt
├── gemini/
│   ├── all.txt
│   ├── vless.txt
│   ├── vmess.txt
│   └── trojan.txt
└── meta.json
```

- `generic/*.txt`: پروکسی‌های گذرانده از تست مرحله اول (انتقال شبکه).
- `gemini/*.txt`: پروکسی‌های گذرانده از هر دو مرحله تست (انتقال و جمینای).
- `meta.json`: فراداده‌های غیرمحرمانه چرخه (زمان تولید، شماره چرخه و تعداد کاندیداها به تفکیک پروجکشن).
- فرآیند انتشار کاملاً ایمن و اتمیک است: تغییرات قبل از استیج‌شدن در گیت اعتبارسنجی شده و تمیز بودن درخت کاری مخزن کنترل می‌شود.

- وضعیت داده‌ها در فایل مشخص‌شده در `state_file` (پیش‌فرض `./gemsub_state.json`) ذخیره شده و به‌طور خودکار با فرمت gzip به‌شکل `./gemsub_state.json.gz` فشرده می‌شود.

## توسعه و اعتبارسنجی

### دستورات بیلد و اعتبارسنجی

تمامی مراحل توسعه و تست‌های یکپارچگی نیازمند تگ بیلد `-tags with_utls` جهت فعال‌سازی شبیه‌سازی uTLS هستند:

```bash
# بررسی فرمت کد
gofmt -l .

# بررسی فضاهای خالی و انتهای خطوط
git diff --check

# تحلیل ایستای کد
go vet -tags with_utls ./...

# اجرای یونیت‌تست‌ها به‌صورت ترتیبی جهت سنجش دقیق زمان‌بندی‌ها
go test -tags with_utls -count=1 -p 1 ./...

# گیت سنجش تداخل همروندی (Race Detector) روی پکیج‌های پروژه
go test -tags with_utls -race -count=1 ./cmd/gemsub ./internal/config ./internal/scheduler ./internal/publisher ./internal/source ./internal/store ./internal/subserver ./internal/tui

# ساخت باینری برنامه
make build
# یا: go build -tags with_utls ./cmd/gemsub
```

> [!NOTE]
> پکیج `internal/tester` به‌دلیل وجود یک خطای تداخل داده بالادستی در مانیتور شبکه `sing-box` (ثبت‌شده با شناسه فنی `TD-008`) بدون فلگ `-race` ارزیابی می‌شود.

## چکسام و اعتبارسنجی اصالت فایل‌ها

تمامی فایل‌های منتشرشده همراه با فایل مرجع `checksums.txt` حاوی هشدارهای SHA-256 ارائه می‌شوند.

### ایمنی اعتبارسنجی خودکار
اسکریپت‌های `scripts/install.sh` و `scripts/install-termux.sh` الزامات امنیتی سخت‌گیرانه‌ای را پیاده‌سازی کرده‌اند:
- تطابق کامل نام فایل (جلوگیری از خطای ناشی از نام‌های مشابه).
- کنترل یکتا بودن ورودی چکسام در فایل.
- بررسی قالب ۶۴ کاراکتری استاندارد هگزادسیمال SHA-256.
- پاک‌سازی خودکار در صورت بروز مغایرت قبل از اکسترکت شدن فایل.
- پشتیبانی کامل از فرمت‌های باینری‌مد (`*<filename>`).

### اعتبارسنجی دستی
```bash
sha256sum --ignore-missing -c checksums.txt
```

## پشتیبانی از پلتفرم‌ها و محدودیت‌های شناخته‌شده

| پلتفرم | معماری | فرمت باینری | مجاری توزیع |
| :--- | :--- | :--- | :--- |
| **لینوکس** | `x86_64` (`amd64`) | Statically linked ELF64 | اسکریپت نصب، `.tar.gz`، `.deb`، `.rpm` |
| **لینوکس** | `arm64` (`aarch64`) | Statically linked ELF64 | اسکریپت نصب، `.tar.gz`، `.deb`، `.rpm` |
| **لینوکس** | `armv7` (`armhf`) | Statically linked ELF32 | اسکریپت نصب، `.tar.gz`، `.deb`، `.rpm` |
| **اندروید / Termux** | `arm64` (`aarch64`) | Position-Independent ELF64 (`DYN`) | اسکریپت نصب ترموکس، `.tar.gz` |
| **ویندوز** | `x86_64` (`amd64`) | Standalone PE64 (`.exe`) | آرشیو مستقل `.zip` |
| **ویندوز** | `arm64` | Standalone PE64 (`.exe`) | آرشیو مستقل `.zip` |

### محدودیت‌های شناخته‌شده
- **اعتبارسنجی در محیط Termux:** باینری arm64 ترموکس از طریق بیلد‌های هرمتیک و تست‌های یکپارچه ارزیابی شده است؛ تست‌های فیزیکی بر روی دستگاه‌های متعدد ادامه دارد.
- **سیستم‌های دسکتاپ:** باینری‌های دسکتاپ macOS همچنان در ماتریس انتشار فعلی تولید یا پشتیبانی نمی‌شوند. نسخه‌های رسمی ویندوز برای معماری‌های x86_64 و arm64 در قالب آرشیو مستقل ZIP پشتیبانی می‌شوند.
- **تداخل داده بالادستی در Sing-Box (`TD-008`):** یک Data Race شناخته‌شده در مانیتور رابط شبکه `sing-box` (`route/network.go`) تحت همروندی بالا در زمان فعال بودن Go Race Detector وجود دارد. این مورد در CI ایزوله شده و در دفترچه بدهی‌های فنی پروژه پیگیری می‌شود.

# gemsub

[English](README.md) | [فارسی](README.fa.md) | [Русский](README.ru.md)

نرم‌افزار `gemsub` یک دیمن خودکار برای ارزیابی، اعتبارسنجی و توزیع کانفیگ‌های پروکسی و سابسکریپشن است. این ابزار لینک‌های خام اشتراک را از منابع بالادستی دریافت کرده، پایداری شبکه در سطح انتقال (Transport) و دسترسی‌پذیری به سرویس هدف را از طریق پروب‌های فعال بررسی می‌کند و در نهایت پیکربندی‌های معتبر و دسته‌بندی‌شده را از طریق یک اندپوینت محلی HTTP یا مخزن گیت ارائه می‌دهد. این برنامه برای شناسایی محدودیت‌های منطقه‌ای، تشخیص مسیرهای مسدود یا ناسازگار، فیلتر کردن گره‌های غیرقابل‌استفاده برای سرویس‌های نیازمند دسترسی تاییدشده (مانند Google Gemini) و همچنین ارائه یک پروجکشن عمومی از سلامت شبکه برای کلاینت‌های استاندارد پروکسی طراحی شده است.

---

## ویژگی‌های کلیدی

- **پروب فعال دو مرحله‌ای:** ترکیب بررسی‌های لایه انتقال شبکه (TCP/TLS/uTLS) با ارزیابی واقعی در لایه اپلیکیشن HTTP روی سرویس‌های هدف (مانند Google Gemini).
- **دو پروجکشن مجزا و مستقل:** ارائه هم‌زمان کانفیگ‌های تاییدشده ویژه جمینای و کانفیگ‌های عمومی سالم در سطح شبکه بر پایه یک Store واحد و مرجع.
- **رابط کاربری تعاملی در ترمینال (TUI):** ساخته‌شده با Bubble Tea و Lip Gloss؛ شامل جدول زنده کانفیگ‌ها، ماسک‌سازی اطلاعات حساس (`[REDACTED]`)، پرچم کشورها، پنجره جزئیات و نمایشگر لاگ‌های سیستمی بر بستر Ring-Buffer.
- **حالت بدون رابط گرافیکی (Headless):** عملکرد سبک در پس‌زمینه برای سرورها، سرویس‌های systemd و محیط‌های محدود بدون راه‌اندازی رابط کاربری TUI.
- **سرور اشتراک محلی HTTP:** تحویل سابسکریپشن‌های خودکار به کلاینت‌هایی نظیر Throne، Sing-box و Clash با قابلیت فیلتر بر اساس پروتکل (`?proto=vless`)، انتخاب فرمت (`base64` یا `raw`) و اندپوینت سلامت.
- **انتشار خودکار در گیت (Git Publishing):** خروجی قطعی و مرحله‌بندی‌شده و ارسال تغییرات (`all.txt`، `vless.txt`، `vmess.txt`، `trojan.txt`، `meta.json`) به مخزن ریموت گیت.
- **ماندگاری داده‌ها و تاریخچه چرخه‌ها:** نگهداری تاریخچه محدود چرخه‌های تست، شمارنده خطاهای گذرا و امتیازدهی پایداری در قالب اسنپ‌شات‌های اتمیک فشرده‌شده با gzip.
- **پروتکل‌های پشتیبانی‌شده:** VLESS، VMess، Trojan و Shadowsocks (`ss://`).

## شروع سریع

راه‌اندازی سریع در لینوکس با یک دستور:

```bash
# ۱. نصب gemsub در مسیر ~/.local/bin
curl -sSfL https://raw.githubusercontent.com/amirreza-a2a/gemsub/main/scripts/install.sh | bash

# ۲. بررسی نصب و مشاهده نسخه
gemsub --version

# ۳. ایجاد فایل پیکربندی حداقلی
cat <<'EOF' > config.json
{
  "sources": [
    "https://raw.githubusercontent.com/AvenCores/goida-vpn-configs/main/githubmirror/1.txt"
  ],
  "fetch_interval": "1h",
  "test": {
    "timeout": "10s",
    "gemini": {
      "block_phrases": [
        "isn't currently supported in your country",
        "not available in your country",
        "not available in your region"
      ]
    }
  },
  "serve": {
    "listen": "127.0.0.1:8765",
    "path": "/sub",
    "format": "base64"
  }
}
EOF

# ۴. اجرای gemsub در حالت تعاملی TUI
gemsub -config config.json
```

پس از اجرا، `gemsub` بلافاصله یک چرخه آزمایشی اولیه را آغاز کرده و کانفیگ‌های تاییدشده را در نشانی `http://127.0.0.1:8765/sub` ارائه می‌دهد.

## نصب

### لینوکس

#### اسکریپت نصب خودکار (پیشنهادی)

اسکریپت خودکار نصب لینوکس به‌صورت هوشمند معماری سیستم را شناسایی کرده، آرشیو نسخه متناسب را دانلود می‌کند، اعتبار چکسام SHA-256 را با `checksums.txt` می‌سنجد و در نهایت فایل باینری را به‌طور اتمیک و بدون نیاز به دسترسی روت در `~/.local/bin` نصب می‌نماید:

```bash
curl -sSfL https://raw.githubusercontent.com/amirreza-a2a/gemsub/main/scripts/install.sh | bash
```

برای نصب یک نسخه مشخص:

```bash
curl -sSfL https://raw.githubusercontent.com/amirreza-a2a/gemsub/main/scripts/install.sh | bash -s -- -v v0.1.0
```

برای نصب در سطح کل سیستم در مسیر `/usr/local/bin` (نیازمند دسترسی root):

```bash
curl -sSfL https://raw.githubusercontent.com/amirreza-a2a/gemsub/main/scripts/install.sh | bash -s -- --system
```

#### نصب دستی از آرشیو

۱. آرشیو مناسب معماری سیستم خود را از بخش GitHub Releases دانلود کنید:
   - `x86_64` (`amd64`): `gemsub_Linux_x86_64.tar.gz`
   - `arm64` (`aarch64`): `gemsub_Linux_arm64.tar.gz`
   - `armv7` (`armhf`): `gemsub_Linux_armv7.tar.gz`
۲. فایل `checksums.txt` را دریافت کرده و اصالت فایل را بررسی نمایید:
   ```bash
   sha256sum --ignore-missing -c checksums.txt
   ```
۳. فایل باینری را استخراج کرده و در مسیر باینری‌های کاربر نصب کنید:
   ```bash
   tar -xzf gemsub_Linux_x86_64.tar.gz
   install -m 755 gemsub ~/.local/bin/gemsub
   ```

#### بسته‌های نصبی لینوکس (.deb / .rpm)

بسته‌های سیستمی، فایل اجرایی را در مسیر استاندارد مدیریت پکیج لینوکس یعنی `/usr/bin/gemsub` و الگوی کانفیگ را در `/etc/gemsub/config.example.json` قرار می‌دهند.

در دبیان / اوبونتو:
```bash
sudo dpkg -i gemsub_<version>_linux_<arch>.deb
```

در ردهت / فدورا:
```bash
sudo rpm -i gemsub_<version>_linux_<arch>.rpm
```

#### معماری‌های پشتیبانی‌شده در لینوکس
- `x86_64` / `amd64` (پردازنده‌های ۶۴ بیتی Intel/AMD)
- `arm64` / `aarch64` (پردازنده‌های ۶۴ بیتی ARM)
- `armv7` (پردازنده‌های ۳۲ بیتی ARMv7)

#### مسیر ارتقا
اجرای مجدد اسکریپت نصب خودکار، آخرین نسخه پایدار را دریافت، راستی‌آزمایی و جایگزین می‌کند، در حالی که فایل‌های کانفیگ و وضعیت سیستم دست‌نخورده باقی می‌مانند.

### اندروید / ترموکس (Termux)

> [!NOTE]
> این بسته یک **فایل اجرایی مستقل سازگار با ترموکس** است و در حال حاضر یک پکیج رسمی در مخزن بالادستی `termux-packages` محسوب نمی‌شود. اعتبارسنجی زنده روی دستگاه‌های فیزیکی همچنان در دست پیگیری است؛ با این حال، صحت عملکرد آن از طریق بیلد ایزوله و تست‌های یکپارچه‌سازی شبیه‌سازی‌شده تایید شده است.

#### معماری پشتیبانی‌شده
- دستگاه‌های اندرویدی مبتنی بر معماری `arm64` (`aarch64`) که محیط ترموکس را اجرا می‌کنند.

#### اسکریپت نصب خودکار در ترموکس
دستور زیر را مستقیماً درون محیط خط فرمان ترموکس اجرا کنید:

```bash
curl -sSfL https://raw.githubusercontent.com/amirreza-a2a/gemsub/main/scripts/install-termux.sh | bash
```

عملکرد این اسکریپت:
- اجرای دستورات را منحصراً در فضای کاربری ترموکس تایید می‌کند.
- سازگاری معماری دستگاه با پردازنده‌های ۶۴ بیتی ARM (`aarch64`) را بررسی می‌نماید.
- آرشیو اختصاصی `gemsub_Termux_arm64.tar.gz` را دانلود می‌کند.
- اصالت چکسام SHA-256 را مطابق با `checksums.txt` می‌سنجد.
- فایل اجرایی را مستقیماً و بدون نیاز به دسترسی `root` یا `sudo` در `$PREFIX/bin/gemsub` نصب می‌کند.

#### مشخصات فنی و محدودیت‌های ترموکس
- **فرمت باینری:** بیلد به‌صورت Pure Go و کاملاً مستقل از Position (PIE) از نوع ELF `DYN` با مفسر `/system/bin/linker64` و متصل به DNS سیستمی اندروید انجام شده است.
- **دسترسی کلیپ‌بورد:** کپی در محیط TUI با کلید `y` نیازمند ابزارهای پکیج `termux-api` (`pkg install termux-api`) است؛ در غیر این صورت پیشنهاد می‌شود از حالت بدون رابط کاربری (`-headless`) استفاده نمایید.

## نحوه استفاده

### حالت رابط کاربری تعاملی (TUI)

برای باز کردن رابط کاربری تعاملی ترمینال، مسیر فایل کانفیگ را به برنامه پاس دهید:

```bash
gemsub -config config.json
```

#### کلیدها و کنترل‌ها

| کلید | زمینه | عملکرد |
| :--- | :--- | :--- |
| `Up` / `k` | فهرست کانفیگ‌ها | حرکت به ردیف بالا |
| `Down` / `j` | فهرست کانفیگ‌ها | حرکت به ردیف پایین |
| `PageUp` / `Ctrl+B` | فهرست کانفیگ‌ها | اسکرول به صفحه قبل |
| `PageDown` / `Ctrl+F` | فهرست کانفیگ‌ها | اسکرول به صفحه بعد |
| `Home` / `g` | فهرست کانفیگ‌ها | پرش به ابتدای فهرست |
| `End` / `G` | فهرست کانفیگ‌ها | پرش به انتهای فهرست |
| `Enter` / `Space` | فهرست کانفیگ‌ها | باز/بسته کردن پنجره جزئیات کانفیگ |
| `s` | فهرست کانفیگ‌ها | جابجایی فیلتر میان همه کانفیگ‌ها و موارد ارائه‌شدنی |
| `y` | فهرست کانفیگ‌ها | کپی لینک پروکسی انتخابی در کلیپ‌بورد سیستم |
| `Tab` | سراسری | جابجایی فوکوس میان فهرست کانفیگ‌ها و پنل لاگ‌ها |
| `l` (یا `1`-`4`) | پنل لاگ | تغییر سطح فیلتر لاگ‌ها: `DEBUG` ← `INFO` ← `WARN` ← `ERROR` |
| `q` / `Ctrl+C` | سراسری | خروج ایمن، ذخیره وضعیت در دیسک و بستن برنامه |

حداقل ابعاد مجاز پنجره ترمینال **۸۰ ستون در ۲۴ سطر** است.

#### ماسک‌سازی اطلاعات حساس
برای حفظ امنیت و جلوگیری از افشای تصادفی، مقادیر حساس (مانند رمزهای عبور، شناسه‌های خصوصی UUID و توکن‌های کوئری) در نمای TUI با برچسب قرمز `[REDACTED]` پوشانده می‌شوند (مانند `vless://[REDACTED]@host:port`). با این حال، هنگام استفاده از کلید `y` برای کپی، لینک اصلی و کامل با تمامی مشخصات در کلیپ‌بورد ذخیره می‌گردد.

### حالت بدون رابط کاربری (Headless)

برای استفاده در سرورها، سرویس‌های پس‌زمینه لینوکس (مانند systemd) یا سشن‌های خودکار ترموکس:

```bash
gemsub -headless -config config.json
```

در این حالت:
- رابط کاربری TUI راه‌اندازی نمی‌شود.
- لاگ‌های ساختاریافته مستقیماً در خروجی خطای استاندارد (`stderr`) درج می‌گردند.
- برنامه تا زمان دریافت سیگنال‌های `SIGINT` یا `SIGTERM` فعال می‌ماند و هنگام خروج، تمامی فرآیندهای پس‌زمینه با تکمیل ذخیره‌سازی وضعیت بسته می‌شوند.

---

### فلگ‌های خط فرمان

```text
Usage of gemsub:
  -config string
        path to config file (default "./config.json")
  -flag-mode string
        country flag presentation mode: auto, unicode, ascii
  -headless
        run without the TUI (daemon + sub server only)
  -limit int
        limit number of parsed candidates to probe per cycle (0 = unlimited)
  -publish
        enable git publishing after test cycles (overrides config)
  -v	print version information and exit (shorthand)
  -version
        print version information and exit
```

## پیکربندی

فایل تنظیمات با فرمت JSON نگارش می‌شود. یک نمونه آماده در فایل `config.example.json` موجود است. مقادیر ارائه‌شده در این نمونه صرفاً جنبه آموزشی و نمایشی دارند و ممکن است با مقادیر پیش‌فرض توکار ذکرشده در جدول مرجع زیر تفاوت داشته باشند.

```json
{
  "sources": [
    "https://raw.githubusercontent.com/AvenCores/goida-vpn-configs/main/githubmirror/1.txt"
  ],
  "fetch_interval": "3h",
  "test": {
    "health_url": "https://www.gstatic.com/generate_204",
    "health_timeout": "4s",
    "gemini": {
      "url": "https://gemini.google.com/",
      "block_phrases": [
        "isn't currently supported in your country",
        "not available in your country",
        "not available in your region"
      ]
    },
    "timeout": "10s",
    "dial_timeout": "4s",
    "concurrency": 40,
    "rate_limit_rps": 20,
    "max_retries": 2,
    "retry_backoff": "1s",
    "max_inconclusive_cycles": 2
  },
  "serve": {
    "listen": "127.0.0.1:8765",
    "path": "/sub",
    "format": "base64"
  },
  "publishing": {
    "enabled": false,
    "repository": "~/gemsub-subscriptions",
    "branch": "main",
    "remote_url": "git@github.com:your-user/your-subscriptions.git"
  },
  "state_file": "./gemsub_state.json",
  "headless": false
}
```

### راهنمای تنظیمات

| گزینه | نوع | اجباری | پیش‌فرض | توضیحات |
| :--- | :--- | :---: | :--- | :--- |
| `sources` | `[]string` | **بله** | — | فهرست آدرس‌های اینترنتی یا مسیر فایل‌های محلی حاوی لینک‌های اشتراک |
| `fetch_interval` | `string` | **بله** | — | فاصله زمانی بین دوره‌های تست (حداقل `"1m"`، مثلاً `"3h"` یا `"45m"`) |
| `test.health_url` | `string` | خیر | `"https://www.gstatic.com/generate_204"` | اندپوینت سبک جهت ارزیابی اولیه اتصال در سطح شبکه |
| `test.health_timeout` | `string` | خیر | `"4s"` (یا `dial_timeout`) | مهلت زمانی بررسی اتصال در سطح لایه انتقال |
| `test.gemini.url` | `string` | خیر | `"https://gemini.google.com/"` | آدرس هدف برای اعتبارسنجی در لایه اپلیکیشن جمینای |
| `test.gemini.block_phrases` | `[]string` | **بله** | — | عبارت‌های متنی نشان‌دهنده مسدودسازی منطقه‌ای در بدنه پاسخ |
| `test.timeout` | `string` | **بله** | — | حداکثر زمان مجاز برای کل مراحل تست یک پروکسی |
| `test.dial_timeout` | `string` | خیر | `"4s"` | مهلت زمانی برقراری اتصال TCP و هندشیک TLS |
| `test.concurrency` | `int` | خیر | `20` | حداکثر تعداد تست‌های هم‌زمان در هر چرخه |
| `test.rate_limit_rps` | `int` | خیر | `0` (نامحدود) | محدودیت سراسری تعداد درخواست بر ثانیه در حین تست |
| `test.max_retries` | `int` | خیر | `2` | تعداد تلاش مجدد در صورت بروز خطاهای نامشخص |
| `test.retry_backoff` | `string` | خیر | `"1s"` | فاصله زمانی مکث میان تلاش‌های مجدد |
| `test.max_inconclusive_cycles` | `int` | خیر | `2` | سقف مجاز چرخه‌های متوالی نامشخص قبل از حذف کانفیگ از لیست خروجی |
| `serve.listen` | `string` | خیر | `"127.0.0.1:8765"` | آدرس و پورت اتصال سرور اشتراک HTTP محلی |
| `serve.path` | `string` | خیر | `"/sub"` | مسیر URL تحویل سابسکریپشن |
| `serve.format` | `string` | خیر | `"base64"` | فرمت رمزنگاری خروجی: `"base64"` یا `"raw"` |
| `publishing.enabled` | `bool` | خیر | `false` | فعال‌سازی انتشار خودکار کانفیگ‌های سالم در مخزن گیت |
| `publishing.repository` | `string` | مشروط | — | مسیر محلی مخزن گیت در سیستم (در صورت فعال بودن پابلیشر الزامی است) |
| `publishing.branch` | `string` | خیر | `"main"` | شاخه مقصد برای ثبت کامیت‌ها در گیت |
| `publishing.remote_url` | `string` | مشروط | — | آدرس ریموت گیت برای اعتبارسنجی منبع مخزن |
| `state_file` | `string` | خیر | `"./gemsub_state.json"` | مسیر فایل دیسک جهت ذخیره اسنپ‌شات و تاریخچه کانفیگ‌ها |
| `headless` | `bool` | خیر | `false` | اجرای پیش‌فرض در حالت بدون TUI |

## مدل تست و اعتبارسنجی کانفیگ‌ها

فرآیند ارزیابی در `gemsub` طی یک پایپ‌لاین چند مرحله‌ای و دقیق انجام می‌شود تا تضمین گردد تنها پروکسی‌های سالم و مطمئن ارائه می‌شوند:

```text
منابع خام ← دریافت لینک‌ها ← نرمال‌سازی و حذف موارد تکراری
                                       ↓
                     مرحله ۱: بررسی سلامت انتقال (Transport)
                       (اتصال TCP و هندشیک TLS / uTLS)
                                       ↓
                     مرحله ۲: ارزیابی سرویس هدف (Application)
                       (ارسال درخواست HTTP به سرویس هدف)
                                       ↓
                     بررسی محتوا و پالایش بر اساس ضوابط
                                       ↓
                     پایگاه داده مرجع (Store) و به‌روزرسانی وضعیت
```

۱. **دریافت و نرمال‌سازی:** دریافت اشتراک‌ها، استخراج پارامترهای هر پروتکل و نرمال‌سازی پیوندها جهت جلوگیری از پردازش مکرر لینک‌های مشابه.
۲. **بررسی سلامت لایه انتقال:** تست اتصال شبکه با هسته `sing-box` و شبیه‌سازی دقیق فینگرپرینت مرورگرها از طریق uTLS. در صورت شکست اتصال TCP، خطای هندشیک یا عدم پاسخ اندپوینت سلامت، وضعیت با خطای انتقال ثبت می‌گردد (`conn_refused`, `timeout`, `tls_error`, `reality_error`).
۳. **اعتبارسنجی در لایه اپلیکیشن:** پروکسی‌هایی که سلامت انتقال آن‌ها احراز شود وارد مرحله تست درخواست روی سرویس هدف می‌گردند.
۴. **امتیازدهی پایداری و تاریخچه دوره‌ای:**
   - برای هر کانفیگ یک بافر حلقوی محدود از وضعیت تست‌های اخیر ذخیره می‌گردد.
   - افت اتصال‌های مقطعی با وضعیت `inconclusive` مشخص شده و کانفیگ‌هایی که قبلاً سابقه عبور موفق داشته‌اند، تا سقف `test.max_inconclusive_cycles` در لیست اشتراک حفظ می‌شوند.
   - عبور موفق و پیوسته موجب افزایش امتیاز پایداری شده و اولویت نمایش و رتبه‌بندی را تعیین می‌کند.

## اعتبارسنجی اختصاصی جمینای

ابزارهای عمومی بررسی پروکسی معمولاً به پینگ TCP یا تست اندپوینت Google 204 بسنده می‌کنند. این شیوه برای سرویس Google Gemini ناکارآمد است زیرا:

۱. **محدودیت‌های موقعیت مکانی (Geoblocking):** پروکسی‌های واقع در کشورهای پشتیبانی‌نشده (یا آی‌پی‌هایی با شناسایی جغرافیایی نادرست) با وجود اتصال به CDN گوگل، می‌توانند با صفحات ممانعت از دسترسی مواجه شوند.
۲. **مسدودسازی پنهان:** در برخی محیط‌ها، اندپوینت‌های جمینای هنگام اعمال فیلتر منطقه‌ای یا سیاست‌های دسترسی ممکن است کدهای وضعیت HTTP 200 یا 403 حاوی متن‌های عدم پشتیبانی بازگردانند:
   - *"isn't currently supported in your country"*
   - *"not available in your country"*
   - *"not available in your region"*
۳. **شناسایی و قطع ارتباط TLS:** در برخی سناریوها، زیرساخت‌های لبه گوگل ممکن است هندشیک‌های TLS غیرمرورگری را شناسایی کرده یا آنها را محدود (Throttle) کنند.

نرم‌افزار `gemsub` برای پاسخ به این شرایط، با استفاده از کتابخانه uTLS هندشیک کلاینت مرورگر را شبیه‌سازی کرده، نشست HTTP واقعی با `https://gemini.google.com/` برقرار می‌نماید و بدنه پاسخ دریافتی را بر اساس عبارت‌های `block_phrases` ارزیابی می‌کند. کانفیگ‌های مواجه‌شده با فیلتر منطقه‌ای با برچسب خطای `region_blocked` علامت‌گذاری و تفکیک می‌شوند.

## پروجکشن‌های جنریک در برابر جمینای

پایگاه داده مرجع `Store` دو خروجی مجزا و مستقل از هم نگهداری می‌کند:

```text
                    ┌─────────────────────────┐
                    │       وضعیت Store       │
                    └────────────┬────────────┘
                                 │
                 ┌───────────────┴───────────────┐
                 ▼                               ▼
     Store.NetworkPassing()               Store.Passing()
    [پروجکشن عمومی شبکه]               [پروجکشن تاییدشده ویژه جمینای]
                 │                               │
                 ▼                               ▼
       /sub/generic یا                 /sub/gemini یا
       /sub?projection=generic          /sub?projection=gemini
```

- **پروجکشن عمومی (`Store.NetworkPassing()`):** شامل تمام پروکسی‌هایی که سلامت لایه انتقال (`https://www.gstatic.com/generate_204`) را با موفقیت پشت سر گذاشته‌اند، فارغ از اینکه جمینای به آن‌ها اجازه دسترسی بدهد یا خیر. این گزینه برای وب‌گردی عمومی و کارهای روزمره ایده‌آل است.
- **پروجکشن جمینای (`Store.Passing()`):** تنها شامل کانفیگ‌هایی است که هم سلامت اتصال شبکه و هم آزمون اختصاصی اپلیکیشن جمینای را گذرانده‌اند. مناسب برای ابزارهای هوش مصنوعی و خدمات حساس به لوکیشن.

## رفتار پابلیشر و ساب‌سرور

### ساب‌سرور محلی HTTP

اندپوینت‌های ارائه‌دهنده اشتراک زنده به کلاینت‌ها:

- **اندپوینت پایه:** `http://127.0.0.1:8765/sub` (به‌طور پیش‌فرض پروجکشن جمینای را برمی‌گرداند).
- **اندپوینت اختصاصی عمومی (جنریک):** `http://127.0.0.1:8765/sub/generic`
- **اندپوینت اختصاصی جمینای:** `http://127.0.0.1:8765/sub/gemini`
- **اندپوینت سلامت و آمار:** `http://127.0.0.1:8765/healthz`

#### پارامترهای Query

- `projection=generic` یا `projection=gemini`: تعیین پروجکشن روی اندپوینت پایه `/sub`.
- `proto=vless`، `proto=vmess` یا `proto=trojan`: فیلتر سابسکریپشن بر اساس پروتکل (یا با نام مستعار `protocol=`).
- `format=raw` یا `format=base64`: تعیین فرمت خروجی به ازای هر درخواست.

مثال‌ها:
```bash
# دریافت سابسکریپشن جنریک به صورت متن خام
curl -s "http://127.0.0.1:8765/sub/generic?format=raw"

# دریافت کانفیگ‌های VLESS سازگار با جمینای با انکودینگ Base64
curl -s "http://127.0.0.1:8765/sub/gemini?proto=vless&format=base64"

# مشاهده آمار و وضعیت ساب‌سرور
curl -s "http://127.0.0.1:8765/healthz"
```

### لایه انتشار در گیت (Git Publishing)

در صورت فعال‌سازی `publishing.enabled`، برنامه در انتهای هر چرخه تست، پیکربندی‌های تاییدشده را به مخزن گیت متصل اضافه و Push می‌کند:

- `all.txt`: تمامی کانفیگ‌های قابل ارائه (یکتا و مرتب‌شده بر اساس امتیاز).
- `vless.txt`: کانفیگ‌های مجاز پروتکل `vless://`.
- `vmess.txt`: کانفیگ‌های مجاز پروتکل `vmess://`.
- `trojan.txt`: کانفیگ‌های مجاز پروتکل `trojan://`.
- `meta.json`: متادیتای غیرمحرمانه دوره (شامل برچسب زمان، شماره چرخه و آمار کانفیگ‌ها).

فرآیند انتشار کاملاً امن و بهینه است: اگر در طول چرخه وضعیت هیچ کانفیگی تغییر نکند، عملیات گیت متوقف شده و هیچ کامیت بیهوده‌ای ارسال نمی‌شود.

## ماندگاری داده‌ها و مدیریت وضعیت

نرم‌افزار `gemsub` وضعیت پروکسی‌ها را با یک ساختار اتمیک روی دیسک ذخیره می‌کند:

- داده‌ها در فایل `state_file` (پیش‌فرض `./gemsub_state.json`) نوشته شده و نسخه فشرده `./gemsub_state.json.gz` نیز به‌طور خودکار نگهداری می‌شود.
- نوشتن ابتدا در یک فایل موقت انجام شده و سپس با عملیات اتمیک تغییر نام (Rename) جایگزین می‌گردد تا از خرابی فایل در زمان قطعی ناگهانی برق یا کرش سیستم جلوگیری شود.
- هنگام راه‌اندازی، `gemsub` پیش از آغاز چرخه جدید پروب‌ها، وضعیت ذخیره‌شده کانفیگ‌ها را بازیابی می‌کند تا ساب‌سرور HTTP بتواند بدون نیاز به انتظار برای اتمام یک دوره کامل تست، پیکربندی‌های معتبر بازیابی‌شده را ارائه دهد.

## توسعه و ساختار پروژه

پروژه به زبان Go پیاده‌سازی شده و مرزبندی‌های معماری کاملاً مشخصی دارد:

```text
gemsub/
├── cmd/gemsub/               # نقطه ورود اصلی برنامه و مدیریت چرخه حیات
├── internal/
│   ├── config/              # پارس و اعتبارسنجی فایل پیکربندی JSON
│   ├── source/              # دریافت سابسکریپشن از منابع اینترنتی و فایل‌ها
│   ├── parser/              # پارس پیوندهای پروتکل (VLESS, VMess, Trojan, Shadowsocks)
│   ├── tester/              # موتورهای پروب (سلامت شبکه و بررسی اختصاصی جمینای)
│   ├── store/               # پایگاه مرجع وضعیت کانفیگ‌ها، امتیازدهی و پروجکشن‌ها
│   ├── subserver/           # سرور تحویل سابسکریپشن تحت پروتکل HTTP
│   ├── publisher/           # ماژول ارسال خودکار تغییرات به مخزن گیت
│   ├── tui/                 # رابط کاربری تعاملی ترمینال (Bubble Tea)
│   ├── logging/             # زیرساخت لاگین ساختاریافته و بافر حلقوی
│   ├── clipboard/           # یکپارچه‌سازی ایمن با کلیپ‌بورد سیستم‌عامل
│   └── version/             # متادیتای تزریق‌شده نسخه هنگام کامپایل
└── scripts/                 # اسکریپت‌های نصب و تست‌های یکپارچگی ایزوله
```

## فرآیند انتشار (Release Process)

انتشار نسخه‌ها به‌صورت تگ‌محور و از طریق GitHub Actions و GoReleaser اتوماسیون شده است:

۱. **ثبت تگ نگارش:** انتشار نسخه جدید با Push کردن تگ معنایی آغاز می‌شود:
   ```bash
   git tag -a v0.1.0 -m "Release v0.1.0"
   git push origin v0.1.0
   ```
۲. **پایپ‌لاین خودکار (`.github/workflows/release.yml`):**
   - مرحله `validate` دستورات `go vet` و `go test` را با حداقل دسترسی (`contents: read`) اجرا می‌کند.
   - مرحله `release` ابزار GoReleaser v2 (`v2.18.1`) را با سطح دسترسی (`contents: write`) فراخوانی می‌نماید.
   - ابزار GoReleaser عملیات کامپایل چندسکویی، ساخت آرشیوها، بسته‌های `.deb` و `.rpm`، تولید چکسام‌های `checksums.txt`، تزریق متادیتای بیلد و بارگذاری در GitHub Releases را به انجام می‌رساند.
۳. **راستی‌آزمایی محلی نسخه پیش از انتشار:**
   توسعه‌دهندگان می‌توانند فرآیند بیلد اسنپ‌شات را بدون ارسال تگ گیت به‌صورت محلی بررسی کنند:
   ```bash
   # بررسی صحت ساختار فایل پیکربندی GoReleaser
   make release-check

   # بیلد آزمایشی اسنپ‌شات و ایجاد فایل‌ها در دایرکتوری ./dist
   make release-snapshot
   ```

## چکسام‌ها و تایید اصالت

تمامی بسته‌های منتشرشده همراه با فایل مرجع `checksums.txt` حاوی هشدارهای رمزنگاری SHA-256 ارائه می‌شوند.

### امنیت اعتبارسنجی خودکار
اسکریپت‌های نصبی `scripts/install.sh` و `scripts/install-termux.sh` الزامات امنیتی سفت و سختی را اعمال می‌کنند:
- تطبیق دقیق نام فایل آرشیو (جلوگیری از حملات نام‌گذاری زیررشته‌ای).
- الزام به وجود دقیقا یک رکورد چکسام (رد در صورت نبود یا تکراری بودن شناسه).
- اعتبارسنجی الگوی ۶۴ کاراکتری هگزادسیمال SHA-256.
- پاک‌سازی و مسدودسازی قبل از استخراج (در صورت مغایرت هش، فایل بلافاصله حذف می‌شود).
- پشتیبانی کامل از استاندارد نشانگر باینری (`*<filename>`).

### تایید دستی
```bash
sha256sum --ignore-missing -c checksums.txt
```

## محدودیت‌های شناخته‌شده

- **اعتبارسنجی زمان اجرای ترموکس:** باینری arm64 ترموکس از طریق ساخت هرمتیک، بازرسی ساختار ELF و تست‌های شبیه‌سازی نصب تایید شده است؛ آزمون فیزیکی پایدار روی دستگاه‌های واقعی همچنان پیگیری می‌شود.
- **معماری‌های ترموکس:** دستگاه‌های ۳۲ بیتی ARM و پلتفرم‌های x86 در ترموکس پشتیبانی نمی‌شوند.
- **سیستم‌عامل‌های دسکتاپ:** فایل‌های اجرایی سیستم‌های ویندوز و مک‌اواس در ماتریکس انتشاری کنونی گنجانده نشده‌اند.
- **Race Condition در پکیج بالادستی:** یک خطای مسابقه داده (Data Race) در مانیتور اینترفیس شبکه کتابخانه `sing-box` وجود دارد که در صورت استفاده از ابزار سنجش مسابقه (`-race`) تحت فشار ترافیکی بالا مشاهده می‌شود. این مسئله در سطح تست ایزوله شده و به عنوان بدهی فنی ردیابی می‌گردد (`TD-008`).
